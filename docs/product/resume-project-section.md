# AI Mall 电商客服与售后助手

个人项目｜产品设计与评测｜AI 辅助研发

面向购买者与客服运营，设计覆盖政策咨询、本人订单查询和确认式售后的 AI 助手。针对政策答错与业务误执行风险，定义 MVP、技术取舍、AI 开发任务及验收标准，复用开源电商底座完成原型验证。

- 产品定位与优先级：梳理百炼、Dify、七鱼的官方方案，结合公开合成客服请求与原型失败，优先设计政策问答、订单只读查询和确认式售后；明确缺资料、未登录、异常和人工未接入时的用户路径，产出产品方案与验收矩阵。
- 技术方案与取舍：采用 RAG 支持政策更新与引用追溯，复用 bge-m3／Milvus 与 BM25，按需融合语义和词项结果；库存、订单通过实时 API 获取。关键政策采用原文引用，业务写入采用确认工作流，分别控制事实与操作风险。
- AI 协作与迭代：将需求拆成检索、工具权限、确认流程和评测任务，向开发 AI 指定输入输出、失败分支与反例验收；依据运行日志推进政策误走私人订单查询、引用丢失和虚假完成话术回修，保留失败记录与前后对照。
- 可信体验与资源约束：设计“草稿—确认—提交—追踪”流程，以 Redis 保存确认状态、业务幂等约束防重复办理；补充上下文预算，保留完整规则与工具结果，超限停止推理并提示核对，避免把不完整结果当作办理依据。
- 评测与方案决策：建设149条自建用例及40项 Bitext 适配任务，以本地0.6B模型进行同输入对照。首次中文预留测试通过18/20次代理检查；10类任务各2次开发实验中，文本模型调用25→2次，P95 28.75s→8.31s，据此保留政策直答与业务工具分流策略。

评测口径：40项任务来自20条公开请求的英文及中文适配；检查必要概念、来源与禁止话术。上述为同机离线原型结果，不等同线上解决率或商业降本。
