# AI Mall 电商客服 Agent 与任务评测

个人项目｜AI 产品设计｜Agent 评测｜AI 辅助研发

面向购买者与客服运营，设计覆盖政策咨询、本人订单查询和确认式售后的 Agent。针对政策答错与业务误执行风险，定义 MVP、技术取舍和任务成功标准，组织 AI 辅助研发，建立覆盖回答、工具调用与业务状态的评测及验收流程。

- 产品定位与优先级：梳理百炼、Dify、七鱼的官方方案，结合公开合成客服请求与原型失败，优先设计政策问答、订单只读查询和确认式售后；明确缺资料、未登录、异常和人工未接入时的用户路径，产出产品方案与验收矩阵。
- 技术方案与取舍：采用 RAG 支持政策更新与引用追溯，复用 bge-m3／Milvus 与 BM25，按需融合语义和词项结果；库存、订单通过实时 API 获取。政策分块与原文引用保护完整条款及例外，业务写入采用确认工作流，控制事实与操作风险。
- Agent 评测设计：建立149条自建用例及40项 Bitext 适配任务，定义任务、试次与成功条件，冻结输入及模型、缓存配置，分开开发与首次预留集；结合概念/来源/话术规则、工具轨迹和业务状态断言，检查答复与实际操作结果。
- AI 协作与失败分析：向开发 AI 指定输入输出、失败分支与反例验收，用日志区分路由、检索、生成和权限问题，推进政策误查私人订单、引用丢失、虚假完成话术回修；设计“草稿—确认—提交—追踪”流程，保留失败证据并保护幂等与上下文边界。
- 对照实验与决策：以本地0.6B模型验证语义检索与模型路径、政策直答与任务分流的取舍。10类任务各2次开发对照中，文本模型调用25→2次，P95 28.75s→8.31s；首次中文预留测试通过18/20次代理检查，据此保留分流策略并记录未覆盖场景。

评测口径：40项任务来自20条公开请求的英文及中文适配；检查必要概念、来源与禁止话术。上述为同机离线原型结果，不等同线上解决率或商业降本。
