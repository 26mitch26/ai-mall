# AI Mall 电商客服产品设计与 Agent 评测

个人作品｜需求分析与产品设计｜AI 辅助研发

针对电商客服政策答错、订单状态编造和售后办理不透明的问题，基于现有商城设计智能客服原型。以产品经理视角完成需求分析、服务流程与 AI 验收设计，通过评测决定哪些问题可直接回答、哪些必须查询业务系统或由用户确认。

- 需求分析：研究客服平台与 Agent 开发平台的官方资料，结合公开咨询和原型错误，将需求分为政策咨询、订单查询和售后办理；按答错与误操作风险确定首版优先级，形成产品方案及验收矩阵。
- 产品设计：政策咨询允许访客使用，个人订单要求登录，售后办理先展示草稿再确认；设计拒绝确认、信息不足、操作失败和状态查询路径，明确“提供答复”与“办理完成”的区别，减少错误承诺。
- 技术取舍与 AI 协作：政策采用检索增强（RAG），便于更新和引用原文；订单、库存从业务接口读取。要求分块保留条款与例外，写操作校验身份并取得确认；将规则拆成 AI 开发任务，指定输入输出与反例验收，推动误查订单、虚假转人工等问题修复。
- Agent 评测：以149条自建检索用例和20条公开客服请求构建评测输入；答案检查要点与来源，工具检查权限和参数，流程检查确认与重复提交。开发样本用于回修，首次预留样本检验新问法，保留每次失败及调用记录。
- 验证结果与迭代：在10个任务各运行2次的开发对照中，引入政策原文直答与任务分流，生成调用由25次降至2次；首次中文预留20次试验中18次通过规则检查。针对退款步骤遗漏及运费、保修条件错误补回归，据此保留分流并完善证据选段。

项目范围：调研为桌面研究，20条请求为公开合成数据，中英文适配共40项任务；结果为同机离线规则检查。当前为研发原型，未开展真实用户访谈、商家上线或完整交易验收。
