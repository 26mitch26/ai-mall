# AI Mall 电商客服 Agent 与任务评测

个人项目｜AI 产品设计｜Agent 评测｜AI 辅助研发

面向电商购买者与客服运营，在 AI 辅助下完成竞品桌面研究与用户任务分析，设计政策咨询、订单查询和确认式售后的 MVP、交互流程及异常路径。针对政策答错与业务误执行风险，定义需求优先级、技术取舍与验收标准，通过 Agent 评测驱动迭代。

- 产品调研与需求设计：基于官方文档对比客服及 Agent 平台的知识问答、流程编排与人工接入能力；结合公开客服请求和原型失败，梳理用户任务，确定政策问答、订单只读与确认式售后的 MVP；设计缺资料、未登录和异常路径，产出需求优先级与验收矩阵。
- 技术方案与取舍：采用 RAG 支持政策更新与引用追溯，复用 bge-m3／Milvus 与 BM25，按需融合语义和词项结果；库存、订单通过实时 API 获取。政策分块与原文引用保护完整条款及例外，业务写入采用确认工作流，控制事实与操作风险。
- Agent 评测设计：建立149条自建用例及40项 Bitext 适配任务，定义任务、试次与成功条件，冻结输入及模型、缓存配置，分开开发与首次预留集；结合回答要点、来源和违规承诺检查、工具轨迹与业务状态断言，检查答复与实际操作结果。
- AI 协作与失败分析：向开发 AI 指定输入输出、失败分支与反例验收，用日志区分路由、检索、生成和权限问题，推进政策误查私人订单、引用丢失、虚假完成话术回修；设计“草稿—确认—提交—追踪”流程，保留失败证据并保护幂等与上下文边界。
- 方案验证与迭代：对比模型回答与“政策直答＋任务分流”策略；10类任务各2次开发对照中，文本生成调用25→2次，首次中文预留20次中18次通过预设规则检查。结合失败定位退款步骤与政策条件遗漏，保留分流策略并补充已知错误回归。

范围与口径：调研为官方资料桌面研究，尚未开展真实用户访谈。40项任务来自20条公开合成请求的英文及中文适配；结果为同机离线规则检查，不等同线上解决率或商业降本。
