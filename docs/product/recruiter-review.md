原审查日期：2026-10-06；实现状态核对至2026-10-07。按应届与初级岗位评审项目段落；个人学历、项目周期、履历和现场表达不在当前材料内。此判断不是招聘录用承诺，也不是候选人排名。

我的面试官判断：这个项目值得进入初级 AI 产品经理的技术与产品面试，优势是有实现、失败迭代与可追溯实验。对有经验的业务型产品经理岗位，缺少真实用户研究、商家试点、上线结果与组织协作证据。只保留一个项目时，应围绕一个客服任务讲清产品决策，不以技术数量支撑资历。

## 本轮实际落地与验证

ReAct 模型路径新增 `ai.agent.context.max-characters`，默认12000字符。保留完整规则、工具说明、当前问题和本轮工具轨迹；政策证据按排序以整份输入单元选取，再选择连续的近期历史。被省略的资料不作为本轮已看到的证据。模型客户端另做输入字符上限检查，覆盖直接及降级调用；超限在HTTP调用前拒绝。

必需内容过长时停止推理，给出缩小范围与业务页面核对提示，不虚构办理状态。持久化历史和 Redis 确认状态没有被压缩或删除。这里是预算与选择，没有实现模型总结、动态工具搜索或Agent Skills运行时。

字符数是输入大小代理，不是精确token数，也不保证默认12000字符一定适配4096或2048 token窗口。更换模型前应使用其tokenizer或实际 `prompt_eval_count` 校准，预留输出空间；目前没有新的小模型在线质量或时延实验。

新增10项 JUnit 测试验证：完整历史选择、完整政策与哈希保留、超长政策不截掉例外、完整工具JSON、精确字符边界、HTTP前拒绝且不消耗调用额度、ReAct前拒绝、超长工具结果阻止下一次模型调用、未进入上下文的资料不产生来源与事实支持、降级时不以再次检索但未用于答案的资料进行事后背书。最后一项还移除了冗余的事后检索；没有实测其时延收益。

最终后端相关模块187项测试通过（mall-common62、agent-customer125），失败0、错误0、跳过0；真实语义检索测试未在本轮运行，其他模块历史测试数不并入本次。验收记录见 `eval/results/recruiter-upgrade/validation.json`。

本轮没有实际生成/embedding/重排调用或外部推理费用，没有新增常驻模型。确定性测试适合检查输入预算与状态边界，不能推出回答质量或P95提升。

## 面试答辩必须准备的六个回答

1. 用90秒说明用户、问题、产品目标、两项取舍与一次验证，避免从架构列表开讲。
2. 面试官要求只保留一个方案时，说明小语料BM25或全文上下文方案的取舍，以及什么失败会促使启用混合检索或重排。
3. 解释一个具体错误：例如99元门槛为什么不能支持99元运费，或人为损坏为什么不能从非人为保修推导免费修。
4. 展示一份给AI的任务合同，明确禁止虚构退款/转接、输入输出、正常与反例验收；指出自己的评审反馈在哪里改变方案。
5. 能复述18/20的样本来源、首次预留口径及失败，不将开发集100%当真实解决率，也不把公开数据原回答当商城政策。
6. 如果获得两周和一个测试商家，先确认政策与真实客服渠道，完成登录任务和5至8位用户观察，再决定是否引入更重的模型。人数与时间是试点计划。

最值得补的材料依次是真实用户任务观察、商家政策复核、完整身份与业务状态演示、人工接收回执和完整成功成本。新模型与新框架的引入排在这些证据之后，除非真实失败表明它们能解决当前主要问题。
