# AI-Mall 四岗位简历项目段落

日期：2026-10-07。以下是可按 JD 选择的项目表达。投递前确认本人实际负责的需求、设计、实现与验收；AI 辅助或开源复用不能全部写成个人原创。详解与源码见[岗位证据手册](role-playbook.md)，本轮数量以[验收 JSON](../../eval/results/career-readiness/validation.json)为准。

## 产品经理 / AI 产品经理

**AI-Mall 电商智能客服研发原型｜用户任务设计、交互与验收**

- 围绕政策咨询、实时查单与售后办理拆分 MVP，为证据不足、未登录、拒绝确认和异常恢复定义用户路径与验收标准。
- 将政策条件遗漏和错误来源转成产品风险，设计保留条件与例外的分块策略，用结构实验和失败样例检验设计。
- 推进测试报告对比：区分新增失败、已修复、持续失败和用例增删；基线失效与环境未验证单独提示，帮助判断版本变化。
- 建立离线评测、产品指标与交付证据的对应关系，明确研发原型、合成数据和商业指标的边界；真实用户观察与商家试点待开展。

若使用历史结果，只能附原条件写“同输入开发对照中生成调用从 25 次降至 2 次，首次中文预留 20 次试验中 18 次通过规则检查”，不得改写为客服降本、用户满意度或新盲测成绩。

## Java 后端开发

**AI-Mall 电商与 Agent 服务｜Java 21、Spring Boot、MyBatis、Redis、JWT**

- 在多模块商城基础上维护业务与 Agent 服务边界，结合 JWT、工具权限与确认工作流控制个人数据访问和写操作。
- 为下单设计用户范围内的幂等键与参数指纹，支持同键请求冲突检测及完成结果回放，使用 H2 双线程回归验证重复请求只创建一次业务订单。
- 通过 Redis 草稿状态、版本校验和确认提交处理售后恢复；相关集成测试对模型与下游工具进行模拟，完整真实交易仍待验收。
- 新增受保护的测试报告比较 API，处理基线淘汰、重复身份和环境异常，并保留方法/路径字段以支持报告落盘后的跨轮次匹配。

## AI 应用开发 / Agent 开发

**AI-Mall 智能客服｜RAG、工具调用、证据门控与确认工作流**

- 按问题选择语义、词项或混合召回，结合来源校验和拒答路径约束政策回答，实时订单通过鉴权业务接口读取。
- 为政策引入章节分块，保留完整条件与例外；用证据片段与问题要点匹配减少无依据的政策补写，保留结构实验与错误样例。
- 将模型工具与业务权限、写入确认状态衔接，测试未登录、越权、拒绝确认与重试恢复，区分回答文本与实际业务状态。
- 建立检索、规则与状态分层评测，并用报告差异跟踪回归；本地/兼容云模型入口已实现，真实目标模型质量与资源成本仍需专项验证。

适合 AI 应用与工程岗位；没有基础模型训练、微调、分布式训练或算法创新证据时，不加入这些关键词。

## 测试开发 / 质量平台

**AI-Mall 自动化测试 Agent｜OpenAPI、JUnit、Mockito、MCP、Vue**

- 以 OpenAPI 声明治理测试期望值：成功码无声明则丢弃，未声明错误码降为 4xx 弱断言，校验 AI 生成用例的方法、路径、参数与状态码。
- 将环境可达性与连接噪音独立记录，结合业务码、结构、分页不变式和失败分类提高报告可解释性；明确 `$ref` 当前覆盖限制。
- 新增基线报告对比，按稳定用例身份识别新增失败、修复、持续失败和范围变化，避免随机 UUID 导致误匹配；对歧义与缺失基线显式拒绝。
- 将比较能力接入后台页面和受保护 REST API，并维护 MCP 异步测试句柄；通过离线回归、前端类型检查与构建保留可复现证据。
