## 追问应对

### Q: RAG 全链路是怎么设计的？

**A**: RAG 分为四个阶段：
1. **索引阶段**：文档解析 → 分块 → 向量化 → 存入 Milvus
2. **检索阶段**：向量检索 + BM25 关键词检索 + RRF 融合
3. **重排序阶段**：Cross-Encoder 重排序，提升召回质量
4. **生成阶段**：将检索结果作为上下文，调用大模型生成答案

关键是分块策略和检索优化，我们用固定大小 + 语义分块结合，检索用 RRF 融合向量和关键词结果。

### Q: 向量检索和关键词检索怎么融合？

**A**: 使用 RRF（Reciprocal Rank Fusion）融合：
1. 向量检索返回 Top-K 结果，每个结果有排名
2. BM25 关键词检索返回 Top-K 结果，每个结果有排名
3. RRF 公式：`score = 1/(k + rank1) + 1/(k + rank2)`
4. 按融合分数排序，返回最终结果

这样能同时利用语义理解和关键词匹配，召回效果比单独使用任何一种都好。

### Q: Agent 的记忆系统怎么设计的？

**A**: 分为短期和长期记忆：
1. **短期记忆**：Redis 滑窗存储，保留最近 10 轮对话，24 小时过期
2. **长期记忆**：Milvus 向量化存储，将对话历史向量化后存储，支持相似对话检索

这样既能保证多轮对话的上下文连贯，又能从历史对话中学习。

### Q: 模型路由和熔断器怎么设计的？

**A**: 设计了统一的模型调用层：
1. **模型路由**：根据配置选择主模型（MiMo）或备选模型（OpenAI）
2. **熔断器**：三态熔断器（CLOSED/OPEN/HALF_OPEN）
   - CLOSED：正常调用
   - OPEN：连续失败 5 次，降级到备选模型
   - HALF_OPEN：探测恢复，成功则回到 CLOSED
3. **降级策略**：MiMo 故障时自动切换到 OpenAI，确保服务可用

### Q: Prompt Engineering 怎么做的？

**A**: 针对不同场景设计专用 Prompt：
1. **智能客服**：角色设定 + 工具描述 + 回答格式约束
2. **智能运维**：分析框架 + 输出格式 + 置信度要求
3. **自动化测试**：测试用例模板 + 断言规则 + 报告格式

关键是让大模型理解任务边界，输出结构化结果，便于后续处理。

### Q: 为什么选择 MiMo 而不是 OpenAI？

**A**: 三个原因：
1. **国产模型趋势**：国产大模型是趋势，体现技术视野
2. **MiMo 推理能力强**：在数学推理、代码生成等任务上表现优异
3. **延迟低成本低**：国内部署，网络延迟低，API 价格更便宜

我们通过模型路由实现主备切换，MiMo 故障时自动降级到 OpenAI，确保高可用。
