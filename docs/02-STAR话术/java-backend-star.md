## 追问应对

### Q: 为什么选择多模块架构而不是单体应用？

**A**: 多模块架构有三个优势：
1. **代码复用**：mall-common 被所有模块依赖，避免重复代码
2. **职责清晰**：每个模块职责单一，mall-admin 负责后台，mall-portal 负责前台
3. **独立部署**：可以按需部署单个模块，比如只部署 mall-admin

### Q: Redis 缓存一致性怎么保证？

**A**: 采用 Cache Aside 模式：
1. **读取**：先读缓存，缓存未命中读数据库，然后写缓存
2. **更新**：先更新数据库，再删除缓存
3. **分布式锁**：使用 Redisson 实现分布式锁，防止并发更新导致数据不一致
4. **过期策略**：设置合理过期时间，兜底方案

### Q: Kafka 如何保证消息不丢失？

**A**: 从三个环节保证：
1. **生产者**：使用事务消息，确保消息发送和数据库操作的原子性
2. **Broker**：配置 `acks=all`，确保消息被所有副本确认
3. **消费者**：手动提交 offset，处理完业务逻辑后再提交

### Q: 系统如何保证高可用？

**A**: 从四个层面保证：
1. **应用层**：多实例部署，负载均衡
2. **缓存层**：Redis Cluster 集群
3. **消息队列**：Kafka 集群，副本因子 ≥ 2
4. **数据库**：主从复制，读写分离
