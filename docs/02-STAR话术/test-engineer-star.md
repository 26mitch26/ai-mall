## 追问应对

### Q: 测试金字塔是什么？

**A**: 测试金字塔描述测试用例的分层结构：
1. **底层（多）**：单元测试，测试单个方法/类，速度快、成本低
2. **中层（中）**：集成测试，测试模块间交互，验证集成正确性
3. **顶层（少）**：端到端测试，测试完整业务流程，速度慢、成本高

原则是底层测试多、顶层测试少，因为底层测试更快、更稳定。

### Q: Testcontainers 是什么？为什么用它？

**A**: Testcontainers 是一个 Java 库，可以在测试中启动真实的 Docker 容器。

**为什么用它**：
1. **环境一致**：测试环境与生产环境一致，避免"在我机器上能跑"
2. **自动清理**：测试完成后自动销毁容器，不会污染环境
3. **隔离性**：每个测试用例使用独立容器，互不影响
4. **真实性**：测试真实数据库操作，而不是 Mock

### Q: 如何保证测试数据的可重复性？

**A**: 采取三个策略：
1. **数据初始化**：每个测试开始前，通过 SQL 脚本初始化测试数据
2. **事务回滚**：每个测试方法使用 `@Transactional`，测试完成后自动回滚
3. **容器隔离**：Testcontainers 为每个测试类启动独立容器

### Q: 测试覆盖率多少合适？

**A**: 覆盖率不是越高越好，要平衡成本和收益：
1. **核心业务逻辑**：80%+，确保关键路径覆盖
2. **工具类/通用组件**：90%+，这些代码容易测试
3. **Controller/API 层**：60%+，主要验证接口正确性
4. **总体目标**：70%+，确保基本质量

关键是测试质量而非数量，100% 覆盖率不代表没有 Bug。
