# 面试高频问题 Q&A

## Java 后端方向

### Q1: Spring Boot 自动配置原理是什么？

**A**: Spring Boot 自动配置基于 `@EnableAutoConfiguration` 注解：
1. 通过 `spring.factories` 加载所有自动配置类
2. 使用 `@Conditional` 系列注解判断是否需要配置
3. 通过 `application.yml` 覆盖默认配置

核心是条件装配，只有满足条件时才生效。

### Q2: MyBatis Plus 有什么优势？

**A**: MyBatis Plus 在 MyBatis 基础上增强：
1. **CRUD 自动生成**：单表查询无需手写 SQL
2. **条件构造器**：链式 API 构建查询条件
3. **分页插件**：内置分页功能
4. **代码生成器**：自动生成 Entity/Mapper/Service
5. **逻辑删除**：支持软删除

### Q3: Redis 缓存穿透、击穿、雪崩怎么解决？

**A**:
- **穿透**：查询不存在的数据，缓存和数据库都没有
  - 解决：布隆过滤器拦截 + 缓存空值
- **击穿**：热点 key 过期，大量请求打到数据库
  - 解决：互斥锁 + 永不过期 + 预热
- **雪崩**：大量 key 同时过期
  - 解决：过期时间加随机值 + 集群部署 + 多级缓存

### Q4: 分布式事务怎么保证？

**A**: 根据场景选择方案：
1. **强一致性**：2PC、3PC（性能差）
2. **最终一致性**：TCC、Saga、本地消息表
3. **消息队列**：使用 Kafka 事务消息

我们项目使用 Kafka 事务消息实现订单和库存的最终一致性。

## Agent 工程方向

### Q5: 什么是 Agent？

**A**: Agent 是能够感知环境、做出决策、执行行动的智能体：
1. **感知**：接收用户输入或环境信息
2. **决策**：基于大模型进行推理
3. **行动**：调用工具或执行操作
4. **记忆**：保存对话历史或学习经验

和传统 chatbot 的区别是，Agent 有自主决策能力，能调用外部工具完成复杂任务。

### Q6: ReAct 和 Plan-and-Execute 有什么区别？

**A**:
- **ReAct**：Thought → Action → Observation 循环，适合单步决策
- **Plan-and-Execute**：先规划整体计划，再逐步执行，适合复杂任务

ReAct 更灵活，但可能陷入循环；Plan-and-Execute 更可控，但计划可能不准确。

### Q7: RAG 和微调有什么区别？

**A**:
- **RAG**：检索增强生成，通过检索外部知识补充大模型
  - 优点：无需训练，知识可更新
  - 缺点：检索质量影响答案质量
- **微调**：在特定数据上训练大模型
  - 优点：领域知识内化，推理更快
  - 缺点：需要训练数据，成本高

我们项目使用 RAG，因为电商知识更新频繁，RAG 更灵活。

### Q8: 向量检索的原理是什么？

**A**: 向量检索基于语义相似度：
1. **向量化**：将文本转为高维向量（embedding）
2. **索引**：使用 HNSW、IVF 等算法建立索引
3. **查询**：将查询向量化，在索引中查找最近邻
4. **排序**：按相似度排序，返回 Top-K

和关键词检索的区别是，向量检索能理解语义，比如"手机"和"移动电话"相似度高。

## 测试工程方向

### Q9: 单元测试、集成测试、端到端测试的区别？

**A**:
- **单元测试**：测试单个方法/类，Mock 外部依赖
- **集成测试**：测试模块间交互，使用真实依赖
- **端到端测试**：测试完整业务流程，模拟用户操作

区别在于测试范围和依赖程度，单元测试最快最稳定，端到端测试最慢最脆弱。

### Q10: Mockito 的原理是什么？

**A**: Mockito 基于动态代理：
1. **创建 Mock 对象**：使用字节码生成代理类
2. **录制行为**：`when(method).thenReturn(value)`
3. **验证调用**：`verify(mock).method()`

Mock 对象不执行真实逻辑，只返回预设值，用于隔离被测代码和外部依赖。

### Q11: Testcontainers 如何保证测试隔离？

**A**: Testcontainers 通过三个机制保证隔离：
1. **容器级别**：每个测试类启动独立容器
2. **数据库级别**：使用随机数据库名
3. **清理机制**：测试完成后自动销毁容器

还可以通过 `@Testcontainers` 和 `@Container` 注解控制生命周期。

### Q12: 如何设计测试数据？

**A**: 测试数据设计原则：
1. **最小化**：只包含测试需要的字段
2. **独立性**：每个测试使用独立数据集
3. **可重复**：数据初始化脚本化
4. **易清理**：测试完成后自动清理

我们项目使用 SQL 脚本初始化数据，配合 `@Transactional` 自动回滚。
